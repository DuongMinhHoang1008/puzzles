# Puzzle Studio

TypeScript/Vite frontend for the **38 stable C engines in this repository**. Engines are built locally with Emscripten; no puzzle logic is reimplemented in JavaScript.

This is an implementation preview, **not a completed v1 release**. See `../docs/web-build-notes.md`, `../docs/web-game-coverage.md`, and `release-status.json` for verified results and remaining gates. The deployment workflow intentionally rejects an incomplete release.

## Toolchain

Validated locally: Node **24.19.0**, npm **12.0.2**, Vite **8.3.4**, Perl **5.36.1** (Git for Windows), Emscripten **4.0.20**, Windows x64, installed Chrome. CI uses Ubuntu 24.04 and the same Node/SDK pins. GNU make is not required: the build runner reads the object dependency graph generated by `mkfiles.pl` and compiles it directly.

Install the official SDK in `build/web/emsdk`, run `emsdk install 4.0.20`, then `emsdk activate 4.0.20`. On Linux/macOS, source `emsdk_env.sh` before building. On Windows, the build runner locates this SDK and its bundled Python automatically; `PERL`, `EMCC` and `EMSDK_PYTHON` can override paths.

From the repository root:

```sh
npm --prefix web ci
npm --prefix web run build:engine
npm --prefix web run dev
npm --prefix web run typecheck
npm --prefix web run test
npm --prefix web run build
npm --prefix web run preview
npm --prefix web run test:e2e
```

`build:engine -- --game net` is a partial spike build. It intentionally replaces the asset manifest with Net only. Run the full build again before production; `build:frontend` rejects partial or missing engines. No native/iOS Makefiles are written in the root: generation runs in ignored `build/web/source`.

Add `--debug` to `build:engine` for Emscripten runtime assertions. Default output is optimized production WASM. Debug-only accessor metadata can retain an instance in Chromium's allocation feedback; use production artifacts for retained-instance QA. Full builds discard previous hashed engine files after success.

For Playwright, install Chromium with `cd web && npx playwright install chromium` or set `BROWSER_PATH` to an installed Chrome executable. Browser tests serve **production** output under `/puzzles/`. A development server is not deployment evidence.

All 38 board thumbnails and seed fixtures are checked in. To regenerate them, run the dev server in another terminal, then:

```sh
node tools/web/capture-boards.mjs
npm --prefix web run build:frontend
```

This captures real boards using seed `0`, writes reproducibility fixtures and the runtime string inventory, and enables the generated thumbnails. Use `PREVIEW_URL` to change the capture server URL. Generated thumbnails are intended to be reviewed and committed; engine JS/WASM and `dist` stay ignored.

## GitHub Pages

Remote default branch was verified as **master**. Workflows check builds on PRs/master, and prepare Pages on master or manual dispatch. Actions are pinned to verified release SHAs. `PAGES_BASE` defaults to `/puzzles/`; deployment derives it from the repository name. Hash routes preserve refresh and encoded Game IDs.

Pages currently publishes a preview after the full Linux build and browser checks pass. `release-status.json` explicitly permits preview deployment while preserving incomplete release QA; the strict release check still fails until all release gates pass. The owner must select **Settings → Pages → Source → GitHub Actions**. Deployment success must be verified in Actions and at the public URL.

Puzzle Studio is an independent frontend, not an official Simon Tatham product. Original engine/manual copyrights and MIT notices are preserved in `public/licenses/LICENCE`. UI uses system fonts; short opt-in sounds are synthesized in code, with no third-party audio assets.
